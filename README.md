# dsh-git-panel

DeepSeek Harness 的 Git 面板插件：在会话右侧栏里看变更、读 diff、编辑文件、暂存与提交，提交说明可以直接用 DSH 里已配置的模型生成。

### 深度审阅报 Authentication failed / Unauthorized

- **Gitee 的 fork PR**：Gitee 没有 `refs/pull`，深度审阅必须能从 fork 仓库拉代码。若当前账号读不到
  该 fork（例如 fork 是私有的、或你只有 base 仓库权限），会明确提示 `fork-no-access`。
  处理：换成对 fork 有权限的账号，或让作者把分支推到主仓库。
- **同仓库 PR**：确认令牌包含仓库读写（Gitee 的 projects / GitHub 的 repo）权限。
- 插件拉代码时会禁用本机凭据管理器，只用插件里配的令牌，所以 `git` 命令行里能克隆不代表这里一定行
  （命令行可能用了凭据管理器里另一份凭据）。

## 安装

**在线安装（推荐）**

DSH → 侧边栏「插件」→「安装第三方插件」，填入：

```
github:lcx19970714/dsh-git-panel
```

点安装即可。装完重启一次 DSH（或在「插件」页随便关开一个插件触发重组），会话标题栏右侧就会出现「变更」按钮。

**命令行安装**

```bash
dsh plugin add github:lcx19970714/dsh-git-panel
```

**本地开发**

```bash
git clone https://github.com/lcx19970714/dsh-git-panel.git
cd dsh-git-panel
node scripts/install-profile.mjs      # 建目录联接装进 default profile
```

这条路径下改 `src/` 后跑 `node build/build-client.mjs` 立即生效（客户端热替换，约 1s）。

## 能做什么

| 功能 | 说明 |
|---|---|
| 变更列表 | 列表 / 树形两种显示，可在设置里切换；支持筛选与键盘导航 |
| 查看 diff | 统一 / 并排视图、上下文行数、忽略空白、词级高亮 |
| 编辑并保存 | 文件模式直接改，`Ctrl/Cmd+S` 保存；带内容哈希校验，冲突时二选一 |
| 暂存 / 取消暂存 | 文件行尾 `+` / `−`，分组头可整组操作 |
| 提交 | smart commit：有暂存只提交暂存；没有暂存则先全部暂存再提交 |
| 生成提交说明 | 用 DSH 里配好的模型生成，优先用暂存内容；生成中显示进度 |
| 多仓库 | 项目内仓库、子目录仓库、外部仓库都列在「储存库」里，点选切换 |
| 隐藏仓库 | 用不上的仓库（测试夹具、vendor）在行尾隐藏，只从「储存库」收起、不动仓库；标题行眼睛按钮展开「已隐藏」再取消隐藏 |
| 分支列表 | 一个分支一行，后面两个小标签 `本地` / `远程`：亮 = 有，暗 = 没有；有上游时显示 `↑n ↓m`。点「只有远程」的行会在本地建跟踪分支并切过去 |
| 获取远程更新 | 分支菜单顶部「获取远程更新」执行 `git fetch` 并重读列表——别人新推的分支就在这一步出现 |
| 切换 / 新建分支 | 当前分支贴在「储存库」行的最右侧；只有点它才打开菜单。可切到已有分支，也可输入名字创建并立刻切过去。工作区怎么处理交给 git，会被覆盖就原样报错 |
| 远端仓库 | 第三个页签「远端」：列出账号下的仓库，选中后右侧显示代码概况、Issues 与 PR（含未关闭数量与最近条目）；点「拉取」克隆到项目根下的子文件夹；没账号时直接在页签里添加。登录多个账号时，**每个工作区分别记住自己选中的账号**：切到别的工作区再回来、或重新打开面板都还是上次那个，不会退回第一个 |
| PR 红点 | 远端仓库列表里，有未合并 PR 的仓库带红色数字角标；数量用每个仓库一次轻量请求取（批量、并发上限 6、单仓库失败不影响其它） |
| AI 审阅 PR | PR 详情里点「AI 审阅」：读 PR 的文件 patch，让模型给出总评 + 编号问题清单（严重度 / 文件:行 / 问题 / 怎么改），超长改动会明确标注"只审了一部分" |
| 评论草稿 | AI 同时起草一段给作者的评论（按 1. 2. 3. 讲清问题与调整方式）；草稿在面板里可编辑，**只有点「提交评论」才发到 PR** |
| 审阅模型 | 设置页里「AI 审阅模型」与提交说明模型各自独立配置，互不影响 |
| 门禁状态 | PR 详情顶部并排显示「审查 / 测试 / 合并状态」；审查按人取最新结论聚合，测试状态平台没接口就如实写「平台未提供」 |
| 一键通过 | 一个按钮按平台能力执行：GitHub 只做审查（测试由 CI 决定），Gitee 审查 + 标记测试一起做；某一步失败会照实列出 |
| Gitee 合并门禁 | 仓库要求「测试通过」才能合并时，PR 详情里有「标记测试通过」按钮，不用回 Gitee 网页 |
| PR 详情与合并 | 点开某个 PR 就在面板里读详情、审查（通过 / 请求修改 / 评论）并合并（可选方法与删源分支），不用跳浏览器 |
| 检测更新 | 点版本号执行 `git fetch`，结果显示在版本号左侧 |
| 设置 | 模型、列表/树形、未跟踪文件分组 |

## 三种仓库形态

| 形态 | 面板行为 |
|---|---|
| 项目根就是一个仓库 | 「储存库」里一行，直接用 |
| 项目下有多个仓库 | 自动发现（最深 4 层、跟随目录联接），各占一行 |
| 粘贴路径 | Windows 资源管理器「复制为路径」会带引号（`"H:\repo"`）：添加目录与新建分支的输入框会自动去掉首尾成对的引号，直接粘贴即可 |
| 仓库不在项目里 | 「储存库」标题行 `+` 添加本机目录（该目录自身必须含 `.git`）；只识别这一个目录，不向上找上级仓库也不扫描子目录，行尾可移除 |

项目根只是仓库子目录时，变更列表展示整个仓库的变更（与 VS Code 一致）。

## 配置

设置入口在工具条右侧的齿轮：

- **生成提交说明的模型** — 列出 DSH 当前可用的模型，选中即保存；未配置时生成会提示
- **变更文件的显示方式** — 列表 / 树形
- **未跟踪文件的分组** — 并进「未暂存」（与 VS Code 一致）或单列一组
- **代码托管账号** — 添加 GitHub / Gitee 账号。设置页与「远端」页签里都有跟着平台走的引导和「获取令牌」按钮（GitHub 会预填 `repo` scope，被浏览器拦截时直接把地址显示出来供复制），复制令牌粘进去即可；插件先用它调一次 `/user` 验证，通过后才存进 DSH 凭据服务（`credentialKey('dsh-git-panel', '<provider>')` 的 grant 记录）。插件不读明文配置；令牌只在用户点「显示令牌」时按需取回，列表接口永远不含它。账号可以随时改备注名、换令牌（会重新校验），也可以显示并复制令牌

### 第一次添加账号（GitHub 例）

1. 设置 → 最下面「代码托管账号」，平台选 GitHub
2. 点「打开令牌页面」→ 浏览器打开 GitHub 新建令牌页，`repo` scope 已预填、描述写着 dsh-git-panel → 拉到最下面点 Generate token
3. 复制那串 `ghp_…`（只显示一次）→ 回到面板粘贴 → 「添加账号」
4. 成功会显示「已连接：<你的登录名>」，切到「远端」页签就能看到全部仓库

Gitee 同理，第三步勾 `projects` 即可，其余一致。

## 限制

- 只做暂存、提交与分支切换；不新建/删除分支，不做 push、discard
- 文件模式固定浏览项目根（没有仓库选择器），仓库切换只发生在变更模式的「储存库」里
- 提交会执行仓库自己的 git hooks，失败时原样显示 hook 的输出
- 文件模式的编辑不设语法高亮（diff 视图仍有词级高亮）
